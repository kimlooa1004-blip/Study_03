# 상식 퀴즈 웹 앱 PRD

## 1. 개요

### 1.1 요구 정리

| 항목 | 내용 |
|---|---|
| 누가 | 대학 1학년 학생이 혼자 상식 공부를 하며 푼다. 계정·로그인·다른 사람과의 경쟁은 없다 |
| 무엇을 | 4지선다 상식 퀴즈 웹 앱. 카테고리 4개(한국사, 세계지리, 과학, 예술과 문화), 카테고리마다 10문제, 총 40문제 |
| 왜 | 틀린 문제를 그 자리에서 알고 넘어가게 한다. 답을 고르면 곧바로 정답 여부와 한 줄 해설을 보여 준다 |
| 언제 | 한 판은 카테고리 1개의 10문제. 10문제가 끝나면 점수를 보여 준다 |
| 어디서 | 브라우저에서 파일을 열면 동작한다(`file://`). 서버·빌드·외부 라이브러리·네트워크 요청이 없다. 파일은 `index.html`, `style.css`, `script.js`, `questions.js` 4개 |

### 1.2 게임 모드

공통 규칙: 답을 고르면 선택이 잠기고 곧바로 정답 여부·정답·한 줄 해설·출처를 보여 준다. [다음]을 누르면 다음 문항으로 가고, 마지막 문항에서는 [결과 보기]가 된다. **틀린 문항은 모든 모드에서 0점**이다.

**연습**

| 항목 | 규칙 |
|---|---|
| 시간 제한·힌트 | 없음 |
| 점수 | 맞히면 1점 (한 판 최대 10점) |
| 순위표 | 기록하지 않는다. 시작 화면과 결과 화면에 "순위표에 기록되지 않음"을 표시한다 |
| 틀린 문제 다시 풀기 | 결과 화면의 [틀린 문제 다시 풀기]로 틀린 문항만 다시 푼다. **다시 푼 뒤에도 틀린 문항이 남으면 버튼이 다시 나타나고, 모두 맞힐 때까지 반복할 수 있다.** 점수는 처음 10문제의 결과만 인정하며 다시 푸는 것은 점수에 반영하지 않는다 |

**스피드**

| 항목 | 규칙 |
|---|---|
| 제한 시간 | 문항마다 15초 |
| 시간 초과 | 오답(0점)으로 처리하고 "시간 초과"와 함께 정답·해설을 보여 준 뒤 [다음]을 기다린다 |
| 타이머 | 답을 고르거나 시간이 지나 해설이 나오면 멈추고, [다음]을 누르면 다음 문항에서 15초부터 다시 센다 |
| 점수 | 맞히면 1점 (최대 10점) |
| 순위표 | 기록한다 |

**힌트**

| 항목 | 규칙 |
|---|---|
| 힌트 | 문항마다 1번. 누르면 오답 보기 2개를 지운다(정답 보기와 오답 1개가 남는다) |
| 시간 제한 | 없음 |
| 점수 | 힌트 없이 맞히면 1점, 힌트를 쓰고 맞히면 0.5점 (최대 10점, 0.5 단위로 표시) |
| 순위표 | 기록한다 |

### 1.3 문항 규칙

모든 문항(40개)은 다음 다섯 가지를 만족해야 한다.

1. **정답은 하나만이어야 한다.** 보기 4개 중 정답이 정확히 1개이고 나머지 3개는 명백히 틀려야 한다.
2. **해설에는 확인한 출처를 명시한다.** 작성자가 실제로 확인한 자료의 기관명과 주소(URL)를 적는다. 확인하지 않은 출처를 적거나 지어내지 않는다.
3. **최상급 표현("가장 ~한" 등)이 쓰인 문항은 기준과 시점을 문제에 명시한다.** 기준과 시점에 따라 답이 달라지기 때문이다. 예: "2024년 면적 기준 ~"
4. **해설은 60자 안팎의 한 줄**이다(줄바꿈 없음). 검사기는 80자까지 허용한다.
5. **한 문항의 보기 4개는 서로 달라야 한다.**

### 1.4 설계 결정

요구에 없어서 정한 사항이다. 바꾸고 싶으면 이 단계에서 고친다.

| 사항 | 결정 |
|---|---|
| 판마다 섞기 | 문항 순서와 보기 순서를 모두 섞는다. 다시 푸는 라운드에서도 보기를 새로 섞는다 |
| 순위표 단위 | 게임 모드 × 카테고리별. 스피드·힌트 2개 모드 × 카테고리 4개 = 표 8개, 표마다 상위 5건 |
| 순위표 기록 | 이름, 점수, 날짜. 점수가 같으면 먼저 세운 기록이 위 |
| 이름 받는 시점 | 스피드·힌트 판을 끝낸 결과 화면에서 이름 입력칸(1~10자)과 [기록 저장] 버튼으로 받는다. 기록은 판마다 한 번만 저장되며 저장 뒤 버튼은 비활성이 된다 |
| 정답 표시 | 정답 보기는 초록·✓, 고른 오답은 빨강·✗로 표시하고 "정답"/"오답" 글자도 함께 보여 준다(색에만 의존하지 않는다) |
| 출처 표시 | 해설 아래에 출처의 기관명·주소를 글자로 보여 준다 |
| 스피드 점수 | 맞히면 1점 |
| 날짜 표기 | `YYYY-MM-DD` |
| 문항 데이터 오류 | 카테고리에 문항이 10개 미만이거나 데이터가 없으면 시작 화면에 "문항 데이터를 불러올 수 없음"을 보여 주고 그 카테고리를 시작하지 못하게 한다 |
| 도중에 나가기 | 진행 중인 판은 저장하지 않는다 |
| 문항 작성 | 클로드가 쓰고, 웹에서 출처를 확인해 해설에 적는다. 최종 확인은 사람이 한다 |

## 2. 사용자와 성공 기준

- 학생이 답을 고른 직후 정답 여부와 해설을 보고 다음 문제로 넘어갈 수 있다.
- 10문제가 끝나면 점수가 표시된다.
- 40문제가 모두 1.3의 문항 규칙을 만족한다.
- 서버나 빌드 없이 파일을 열기만 해도 모든 기능이 동작한다.
- 요구하지 않은 기능이 더해지지 않는다(범위 밖은 8절).

흐름: (2단계 이후) 모드 선택 → 카테고리 선택 → 문제 → 해설 → … → 결과. 결과에서 같은 설정으로 다시 하기와 처음으로 돌아가기를 고를 수 있다. 숫자 키 `1`~`4`는 보기 선택, `Enter`는 [다음]이다.

## 4. 데이터

### 4.1 문항 (`questions.js`)

```js
{
  id: "history-01",        // 카테고리접두사-번호, 전체에서 유일
  category: "한국사",
  question: "...",
  choices: ["...", "...", "...", "..."],
  answer: 0,               // choices의 인덱스, 정답은 하나
  explanation: "...",      // 60자 안팎(80자 이하) 한 줄
  source: "..."            // 확인한 출처의 기관명과 주소(URL)
}
```

전역 `QUESTIONS` 배열이며, 파일 끝에서 Node용으로 `module.exports = { QUESTIONS }`를 내보낸다.

### 4.2 순위표 (`localStorage`)

키 `quiz.leaderboard.v1`, 값은 JSON 하나: `{ "<mode>|<category>": [{ name, score, at }] }`. `at`은 기록 시각(밀리초). 표마다 상위 5건만 남긴다.

## 5. `script.js` 구조

위에서 아래로 구역을 나누고 끝에서 순수 로직을 `module.exports`로 내보낸다(브라우저에서는 `typeof document !== 'undefined'`일 때만 `init()` 실행). ES module은 `file://`에서 막히므로 쓰지 않는다.

| 구역 | 함수 | 설명 |
|---|---|---|
| 로직 | `shuffle(arr, rng)`, `pickQuestions(all, category, rng)` | 카테고리 10문항을 순서·보기 모두 섞어 새 객체로 돌려줌. 10개 미만이면 오류 |
| | `scoreFor(mode, correct, hintUsed)` | 연습·스피드 1점, 힌트 0.5/1점, 오답 0점 |
| | `createGame`, `answer`, `timeout`, `useHint`, `nextQuestion`, `isFinished` | 한 판의 진행 |
| | `wrongQuestions`, `retryGame` | 틀린 문항만 다시 푸는 라운드(반복 가능) |
| 순위표 | `addRecord`, `getTop`, `formatDate`, `getStorage` | 저장·조회. 저장소 접근 실패와 깨진 값을 견딤 |
| UI | `startTimer`, 화면 렌더 함수, `init` | DOM을 다루는 코드 |
| 점검 | `validateQuestions`, `selfCheck` | 문항 규칙 검사와 로직 자체 점검. Node에서 실행하며 브라우저에서는 호출하지 않는다 |

타입: `Question`, `Game { mode, category, questions, index, score, results, answered, hintUsed, hidden, isRetry, saved }`, `Feedback { correct, correctIndex, explanation, source, points, timedOut }`.

## 6. 구현 단계와 완료 기준

### 6.0 3단계로 나눈 범위

| 단계 | 이 단계에서 만드는 것 | 이 단계에는 아직 없는 것 |
|---|---|---|
| 1단계 | 연습 모드와 점수: 카테고리 선택, 10문제 진행(문항·보기 섞기), 즉시 정답 여부·한 줄 해설·출처, 맞히면 1점, 결과 화면의 점수, "순위표에 기록되지 않음" 표시, 문항 40개 | 모드 선택 화면, 스피드·힌트 모드, 틀린 문제 다시 풀기, 순위표 |
| 2단계 | 스피드 모드(15초), 힌트 모드(오답 2개 지우기, 0.5점), 모드 선택 화면, 연습 모드의 틀린 문제 다시 풀기(모두 맞힐 때까지 반복) | 점수 저장, 이름 입력, 순위표 |
| 3단계 | 점수 저장과 순위표(localStorage): 스피드·힌트의 이름 입력과 [기록 저장], 모드 × 카테고리별 상위 5건, 저장소 오류 처리 | — (범위 밖은 8절) |

각 단계는 아래 완료 기준을 **모두** 만족하고, 7절의 확인 방법을 실제로 실행해 통과했을 때만 완료로 본다. "확인 방법"의 `자체 점검`은 `script.js` 안의 `selfCheck()`가 돌리는 점검 묶음(`data`, `game`, `hint`, `speed`, `retry`, `board`)이고, `직접 확인 N-Bx`는 사람이 브라우저에서 하는 확인으로 항목은 `IMPL-PLAN.md`의 각 단계에 있다.

### 6.1 1단계: 연습 모드와 점수

모드 선택 화면과 틀린 문제 다시 풀기는 아직 없다(이 단계의 시작 화면은 카테고리 선택이다).

| # | 완료 기준 | 확인 방법 |
|---|---|---|
| 1-1 | 문항 40개(카테고리당 10개)가 문항 규칙 다섯 가지를 만족한다 | 자체 점검 `data` + 직접 확인 1-B10(출처 링크) |
| 1-2 | 카테고리를 고르면 그 카테고리 10문제가 섞인 순서로, 보기도 섞여 나온다. 섞어도 정답 표시가 정답 보기를 가리킨다 | 자체 점검 `game` + 직접 확인 1-B9 |
| 1-3 | 보기를 고르면 곧바로 정답 여부·정답·한 줄 해설·출처가 보이고 같은 문항은 다시 채점되지 않는다 | 자체 점검 `game` + 직접 확인 1-B3, 1-B4 |
| 1-4 | 맞히면 1점, 틀리면 0점이며 10문제 후 `N / 10`이 표시된다 | 자체 점검 `game` + 직접 확인 1-B7 |
| 1-5 | 시작 화면과 결과 화면에 "순위표에 기록되지 않음"이 보인다 | 직접 확인 1-B1, 1-B8 |
| 1-6 | 모드 선택·힌트·타이머·다시 풀기·순위표가 아직 없다(범위 준수) | 직접 확인 1-B11 |
| 1-7 | 문항 데이터가 없거나 10개 미만이면 안내가 보이고 시작되지 않는다 | 자체 점검 `game`(`pickQuestions` 오류) + `questions.js`를 임시로 줄여 직접 확인 |
| 1-8 | `file://`로 열어 동작하고 콘솔 오류·외부 요청이 없다 | 직접 확인 1-B1, 1-B12 |

### 6.2 2단계: 스피드·힌트 모드, 모드 선택, 틀린 문제 다시 풀기

| # | 완료 기준 | 확인 방법 |
|---|---|---|
| 2-1 | 모드 → 카테고리 순으로 고르면 해당 모드로 시작한다 | 직접 확인 2-B1 |
| 2-2 | 스피드: 15초에서 시작, 해설이 나오면 멈추고, [다음]에서 다시 15초부터 센다 | 자체 점검 `speed` + 직접 확인 2-B2 |
| 2-3 | 스피드: 15초가 지나면 0점·"시간 초과"로 정답·해설을 보여 주고 [다음]을 기다린다. 이후 보기를 눌러도 점수는 그대로다 | 자체 점검 `speed` + 직접 확인 2-B3, 2-B4 |
| 2-4 | 힌트: 문항당 1번, 오답 2개가 사라지고 정답은 남는다. 힌트 후 정답 0.5점, 힌트 없이 정답 1점, 오답 0점 | 자체 점검 `hint` + 직접 확인 2-B5, 2-B6 |
| 2-5 | 연습: 틀린 문항만 다시 풀 수 있고, 또 틀린 문항이 남으면 버튼이 다시 나와 모두 맞힐 때까지 반복할 수 있다. 처음 점수는 바뀌지 않고, 틀린 문항이 없으면 버튼이 없다 | 자체 점검 `retry` + 직접 확인 2-B7, 2-B8 |
| 2-6 | 판이 끝나거나 홈으로 나간 뒤 이전 타이머가 동작하지 않는다 | 자체 점검 `speed`(`stop()`) + 직접 확인 2-B9 |
| 2-7 | 1단계 기준(1-1~1-5, 1-7, 1-8)이 계속 통과한다. 1-6은 해제된다 | 자체 점검 전체 + 1단계 직접 확인 항목 다시 |

### 6.3 3단계: 점수 저장과 순위표

## 7. 검증 방법

- **자체 점검**: 점검 코드는 `script.js` 안의 `selfCheck()`에 있어 앱 파일 4개가 유지된다. 브라우저 없이 Node에서 한 줄로 실행한다(Node 설치 필요).

  ```
  cd Study03_Quiz_A
  node -e "const r=require('./script.js').selfCheck(); console.log(r.failures.length ? r.failures.join('\n') : 'OK ' + r.passed + '개 통과'); process.exit(r.failures.length ? 1 : 0)"
  ```

  실패가 있으면 실패한 점검의 이름을 한 줄씩 출력하고 종료 코드 1로 끝난다.
- **직접 확인**: 사람이 `index.html`을 브라우저에서 열어 `IMPL-PLAN.md`의 "직접 확인할 항목"을 하나씩 점검한다. 단계가 끝날 때마다 하고, 확인한 뒤에 다음 단계로 간다.
- **문항 검사기**: `validateQuestions`(`script.js`)가 보기 4개·유일한 정답 인덱스·해설 80자 이하 한 줄·출처 URL·최상급 문제의 "기준"·중복 id·보기 중복을 검사한다. 기계가 확인할 수 없는 "정답이 하나인지"와 "출처가 실제 내용을 뒷받침하는지"는 사람이 확인한다.
- **최종 확인**(3단계 이후)

| 항목 | 방법 |
|---|---|
| 앱 파일이 정확히 4개이고 외부 URL이 없다 | `ls Study03_Quiz_A`, `grep -n "http" Study03_Quiz_A/index.html` 결과 없음 |
| 폭 375px 안팎의 좁은 화면에서 가로 스크롤이 없다 | 브라우저 개발자 도구의 기기 모드로 각 화면 확인 |
